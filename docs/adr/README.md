# 架构决策记录（ADR）

一个决策一页纸，回答四件事：**当时的处境、决定了什么、代价是什么、什么情况下该翻案**。
PR 描述会过期，ADR 不会——它跟着代码走。

## 格式

```
# NNNN. 一句话标题（决策本身，不是问题）

- 状态：提议 / 已接受 / 已废弃（被 NNNN 取代）
- 日期：YYYY-MM-DD

## 背景
处境、约束、支撑这个决定的数字（带机器与窗口）。

## 决定
一句话能说清的做法。

## 后果
买到了什么、付出什么、留下什么风险。

## 备选
考虑过但否掉的路，以及否掉的原因。

## 什么时候该重看
可观测的翻案条件。
```

## 硬约束

任何 ADR 都不得违反下面几条（违反的那条本身才是要讨论的决策）：

1. **计数器单写者**：每个模块的计数只能有一个写线程（`AGENTS.md` §5）。池化必须让模块固定在一条线程上。
2. **新机制默认关闭**：默认行为等于上一个版本（`threadPoolSize = 0`、`queueFullPolicy = kBlock`）。
3. **不新增逐条日志**：丢弃、超时这类高频事件只计数，不打日志（历史上 1 秒 100 万行 WRN 直接打塌吞吐）。
4. **数字要有出处**：机器名、窗口长度、重复次数、噪声范围，四样缺一不可。
5. **命名跟仓库风格**：公开头文件里的枚举带 `k` 前缀（`PushResult`、`QueueFullPolicy`）。
6. **PR 只能由用户提交**：见 [`HARNESS.md`](../../HARNESS.md) §1.1——这里只留指针，不复述，避免两处定义。
