# 0003. 测量时把池化 N 线程绑到 2N 个逻辑核

- 状态：提议（2N 的直接 A/B 还没做，见「什么时候该重看」）
- 日期：2026-11-23

## 背景

`pipeline_benchmark` 的 `--cpus N` 把**整个进程**绑到前 N 个逻辑核（`benchmarks/pipeline_benchmark.cpp:228`，
Windows 用 `SetProcessAffinityMask`、Linux 用 `sched_setaffinity`），默认 0 = 不绑。测池化时线程数是自变量，
必须给每个配置一个与线程数成比例的 CPU 预算，否则“4 线程跑在 28 个逻辑核上”和“16 线程跑在 28 个逻辑核上”
比的是调度运气，不是代码。

这台机器（i7-14700KF）的拓扑是解释 2N 的前提：

| 逻辑 CPU | 物理核 | 说明 |
|---|---|---|
| 0-15 | 8 个 P 核 | 每核 2 个 SMT 兄弟，兄弟对 (0,1)、(2,3)…… |
| 16-27 | 12 个 E 核 | 无 SMT |

`--cpus N` 取的是**从 0 开始的前 N 个**，所以 N 个逻辑核覆盖的物理核数是 **N/2**（N ≥ 2 时）。而池线程是
自旋/让出型热线程：`poolstats` 显示 85.7% 的轮次结束在“输出边满”的 `Pause()` 分支——它们几乎不 park，
一直占着发射端口。两个这样的线程如果落在同一个物理核的上下两个兄弟线程上，就是在抢同一套执行单元。

## 决定

1. 测池化时，`pool N` 配 `--cpus 2N`（N ≤ 8）：N 条热线程对应 N 个物理 P 核，兄弟线程留给主线程（生产者）和中断。
2. `pool 16` 配 `--cpus 28`（全部逻辑核）：2N 已经越过 16 个 P 线程，进入 E 核，按下面的局限处理。
3. 默认仍是 `--cpus 0`（不绑）；只在需要跨批比较时钉核。

## 为什么是 2N（重点）

三条理由，按可信度排序：

1. **逻辑核 = 半个物理核（可直接观测）。** 同一个 P 核的两个逻辑线程共用 L1/L2 与执行端口。把 N 条热线程钉到
   N 个逻辑核，实际只得到 N/2 个物理核——相当于把“8 线程实验”悄悄变成“4 个物理核”。
2. **让预算与自变量成比例（设计选择）。** 2N 使“每条热线程一个物理核”在 N=2/4/8 上都成立；若固定钉 16 个
   P 线程，N=4 时每条线程拥有 2 个物理核，实验条件随 N 变形。
3. **间接实测（不是 2N vs N 的直接 A/B）。** 同为 16 条线程：`--cpus 16`（16 逻辑 = 8 物理）跑串行路径只有
   **0.634 M**，不绑是 **2.6 M**；`--cpus 18` 起第 17/18 条线程落到 E 核，18 模块出现断崖（§1.1 复测）。
   池化 8 线程在 `--cpus 16` 下是 2.588 M。这些支持“逻辑核预算必须覆盖物理核 + 兄弟”，但**不等于**
   证明了 2N 优于 N。

**局限（必须承认）**

- 亲和性是掩码不是分配：OS 仍可能把两条池线程放到同一个物理核上，2N 只保证“有地方可去”；
- 进程级 mask 同时约束生产者主线程，所以“2N 个逻辑核给 N 条热线程”里其实还挤着一个生产者；
- N > 8 时 2N > 16，预算进入 E 核，2N 不再等于“N 个 P 核”——这时它只是一个“更大但异构”的预算。

## 后果

- `PERFORMANCE.zh-CN.md` 第二部分的池化表协议统一写 `pool N -> --cpus 2N`，并在 N > 8 时注明跨到 E 核。
- 跨批比较必须同核预算；`p0` 一律不绑（16 条线程钉在 16 个逻辑核上会 SMT 自撞，见 §1.1 的 `--cpus 16` 数据）。
- 读者不会把“线程数”和“核预算”两件事混起来。

## 如果不绑核

不绑核不是错，是**不控制**。三条后果，按严重程度：

1. **结论不可复现。** WSL2 深链 `p0` 在不绑时，同一二进制同一参数跑出过 2.48 M（60 s 快态），
   也跑出过 0.77 M / 0.66 M / 0.83 M（300 s 慢态）。线程在 P 核与 E 核之间被迁移，无法区分
   “代码变了”还是“被挪走了”——±30% 的差异都会落进噪声。
2. **跨线程数比较被放置运气污染。** 不绑时 4 线程与 16 线程都能用全部 28 个逻辑核：4 线程大概率
   落在 P 核，16 线程一定溢出到 E 核，比的不是“N 线程的代价”。
3. **尾延迟先崩。** 迁移会甩掉 L1/L2 与队列状态；Windows 深链 `p0` 不绑时 p99 = 63 µs，池化钉核
   `p16` 反而只有 44 µs。

但也要说清楚：Windows 不绑的 `p0` 跨批很稳（2.63–2.69 M，60 s 与 300 s 一致），真正不稳的是
WSL2 里会 park/wake 的路径。所以口径是：**不绑得到“这台机器的表现”，绑核得到“这段代码的性质”**。
前者可以发布，后者才能下结论。

## 备选

- **不绑核**：默认路径，但跨批不可比（WSL2 快/慢两态就是这么暴露的）。
- **绑 N 个逻辑核**：把 SMT 争用当成实验条件，等于系统性低估 N 线程的算力；否决。
- **固定绑 16 个 P 线程**：条件不随 N 等比，N=4 时多给了一倍物理核；作为“上限对照”可以，不作为主口径。
- **按物理核掩码绑（`SetThreadAffinityMask` / `GetCpuSetInformation`）**：能真正指定 P 核，但 harness 目前只做
  进程级掩码；属于工具升级，不是本次决策。

## 什么时候该重看

- 补上直接 A/B：`pool 8` 在 `--cpus 8` 与 `--cpus 16` 下各 300 s。若两者差异 <5%，说明 2N 是多余复杂度，
  可退化为“pool ≤ 8 一律 `--cpus 16`”；
- 若引入按键程/物理核绑定（上面备选第 4 条），2N 的口径要改写。
